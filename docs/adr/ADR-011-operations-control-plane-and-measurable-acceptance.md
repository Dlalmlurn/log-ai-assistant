# ADR-011: 运营控制面与可量化验收

**Status:** accepted

## Decision

下一阶段引入 Docker Compose 管理的运营控制面，统一负责周期任务调度、运行记录、质量门禁和高危事件通知。

baseline 构建、日报生成和数据质量对账不再只依赖人工调用 API 或 CLI。每次任务运行必须形成可查询、可重试、可审计的运行记录，并使用确定性的幂等键避免重复执行。

场景验收不使用笼统的“准确率”作为唯一指标。系统基于生成器中的真实标签和贯穿标识，分别计算正常场景误报率、攻击场景检出率、高危检出率、端到端可追踪率和处理延迟。验收阈值必须版本化并随报告保存。

高危和紧急异常通过持久化 outbox 进入通知投递流程。通知失败可以重试，且不阻塞异常事件落库。前端列表仍是正式告警事实来源，外部通知只是投递渠道。

## Context

ADR-010 已完成周期 baseline 和审核覆盖层，但当前主要能力仍存在以下运营缺口：

- baseline 和日报可以手动生成，但没有统一的自动调度和运行历史。
- 数据质量报告可以发现阶段计数差异，但缺少明确的通过、阻断和复核状态。
- 攻击链可以追踪，但没有把检出率、误报率和延迟固化为版本化验收报告。
- 高危异常可以进入异常列表，但没有持久化、可重试的外部通知投递机制。
- 单元测试、P0 链路检查和规模报告各自存在，尚未形成同一套发布验收证据。

如果继续为每项能力增加独立脚本或容器，调度、重试、并发控制和审计语义会逐渐分裂。下一阶段需要先统一运营控制面，再扩展具体任务和通知渠道。

## Alternatives

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 继续由用户手动调用 API 和脚本 | 不采用 | 无法证明任务按期运行，也缺少失败重试和审计记录。 |
| 每个周期任务使用独立 cron 容器 | 不采用 | 调度和锁语义分散，难以统一查询、重试和告警。 |
| 引入 Airflow、Flink CEP 或外部工作流平台 | 暂不采用 | 当前任务规模不足以抵消额外部署和运维成本。 |
| 单一轻量运营控制面 + ClickHouse 运行记录 | 采用 | 符合 Docker-first 基线，能复用现有服务和存储。 |
| 直接发送通知，不保存投递状态 | 不采用 | 进程退出或渠道故障会造成不可追踪的通知丢失。 |
| 只统计总体 accuracy | 不采用 | 类别不平衡时会掩盖攻击漏检和正常场景误报。 |

## Rationale

运营控制面把“何时运行、是否成功、处理了什么数据、能否重试”从业务实现中分离出来。baseline、日报和质量报告仍由各自领域模块生成，控制面只负责编排和记录，不复制业务逻辑。

版本化验收报告可以把代码版本、场景版本、规则版本、baseline 版本和阈值绑定在一起，使发布结论可重复，而不是依赖一次页面演示或口头判断。

outbox 模式先持久化通知意图，再由投递 worker 发送，可以在不影响异常检测主链路的前提下提供可靠通知和失败重试。

## Consequences

- Compose 中新增一个长期运行的 `operations-runner` 服务；通知投递可以作为同一服务的独立 worker 模式运行。
- 首版 scheduler 在单个 Compose 项目中保持单活，不把 ClickHouse 当作分布式锁；手动任务与 scheduler 使用共享锁卷避免同一幂等键并发运行。
- 需要新增任务定义、运行记录、验收报告、验收指标和通知 outbox 的持久化结构。
- 每个周期任务必须声明调度周期、依赖、幂等键、超时、重试策略和数据水位要求。
- baseline 默认在目标日期数据完整后执行 T+1 构建；日报在 baseline 和质量任务完成后执行。
- 同一租户、任务和业务日期只能存在一个成功结果；失败重试不得生成重复 baseline、日报或通知。
- 数据质量对账必须使用对齐的时间窗口。无法解释的差异进入 `needs_review`，不能被标记为通过。
- 场景评测至少分别输出正常误报率、攻击检出率、高危检出率、可追踪率和检测延迟。
- 发布验收必须保存代码提交、场景版本、规则版本、baseline 模型版本和阈值版本。
- 高危通知必须先写入 outbox；投递渠道至少支持 webhook，其他渠道通过 adapter 扩展。
- outbox 状态和投递 attempt 使用追加版本记录表达，避免依赖高频 ClickHouse mutation。
- 通知失败不得阻止 `AnomalyEvent` 落库，也不得把外部通知状态写回并覆盖异常事实。
- Markdown 是日报的规范内容格式；PDF 可以作为导出适配器，但不作为日报数据的第二事实来源。
- 真实 LLM 连通性属于环境验收项。mock 结果可以用于功能测试，但不能计入真实模型验收通过。
- 完整规则管理和动态规则 DSL 不在本 ADR 范围内，应在后续独立 ADR 中定义权限、版本、发布和回滚语义。
